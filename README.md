### Logistic Regression for Health Intent Classification

The project uses **Logistic Regression** as a binary text-classification model to determine whether a user's query is health-related or non-health-related. First, the input text is converted into numerical features using **TF-IDF (Term Frequency–Inverse Document Frequency)** with unigram and bigram features. The classifier is trained using health-related text generated from the disease database and a collection of non-health-related examples. Logistic Regression then learns the relationship between these text features and their corresponding labels, producing a probability for the health-related class. Based on the classification result, the application routes the user's query to the appropriate processing pipeline, such as the disease/health service for health-related queries or the food/general-purpose service for non-health-related queries. Logistic Regression is a supervised machine learning algorithm mainly used for classification problems, where the goal is to decide which category a given input belongs to. Instead of directly giving a category, the model first calculates the probability that the input belongs to a particular class and then uses that probability to make the final decision. In this project, Logistic Regression is used to classify user queries into two categories: **health-related** and **non-health-related**. The model is trained using labeled examples, where health-related queries are assigned one class and non-health-related queries are assigned another class. When a new query is received, the text is first processed using **TF-IDF**, which converts the words and phrases into numerical features based on their importance in the training data. These numerical features are then passed to the Logistic Regression model. During training, the model learns a weight for each feature based on how strongly that feature is associated with each category. For a new query, the model combines these learned weights with the TF-IDF values and calculates the probability of the query belonging to the health-related class. If the probability is high enough, the query is classified as health-related; otherwise, it is classified as non-health-related. In this project, this classification acts as an initial decision-making step that helps route the user's query to the appropriate processing pipeline. Therefore, the overall process is **user query → TF-IDF feature extraction → Logistic Regression → health/non-health classification**.


### Multinomial Naive Bayes Model

Multinomial Naive Bayes is a supervised machine learning classification algorithm that is commonly used for text classification. In this project, it is used to predict a possible disease based on the symptoms and other disease-related text provided by the user. The model is trained using the disease information available in the dataset, where each training example is associated with a particular disease. First, the text is converted into numerical features using TF-IDF, which represents the importance of different words and phrases. The Multinomial Naive Bayes model then learns how strongly these words and phrases are associated with each disease. When a user enters symptoms, the same TF-IDF process converts the input into numerical features, and the model calculates the probability of the input belonging to each disease class. It then selects the disease with the highest probability as the prediction. The model is called “Naive” because it assumes that the features are independent of each other when calculating probabilities. In this project, the overall process is **user symptoms → TF-IDF feature extraction → Multinomial Naive Bayes → disease prediction**.


### CLIP Model

CLIP (Contrastive Language–Image Pre-training) is a machine learning model designed to understand the relationship between **images and text**. Unlike Logistic Regression and Multinomial Naive Bayes, which are used for text classification in this project, CLIP can work with visual information. It is trained to learn how images and their corresponding text descriptions are related. In this project, CLIP is used for **food image recognition**. When a user uploads an image of a food item, the image is given to the CLIP-based service, which compares the visual features of the image with possible food descriptions or labels and determines which one is the closest match. For example, if the user uploads an image of a dosa, CLIP can compare the image with labels such as “dosa”, “pizza”, “burger”, and other food categories and identify the most likely match. The predicted food name can then be used by the application to retrieve additional information such as nutritional values, benefits, or other details from the food database. Therefore, the overall process is **food image → CLIP model → predicted food name → food database → food information**.
